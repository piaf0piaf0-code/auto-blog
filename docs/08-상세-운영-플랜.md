# 08. 상세 운영 플랜 (블로그별·발행량·키워드·자동화)

06(운영 체계 개요)을 **실제 숫자와 블로그별 행동**으로 구체화한 실행 매뉴얼.

---

## 0) 먼저 결정할 것 — bodybalance-labo.com 에 구글애즈?

> 결론 먼저: **애드센스로 수익 내는 콘텐츠 글에 구글애즈로 트래픽을 사오는
> 것은, sa.seaga.co.kr 의 아비트라지와 본질적으로 같은 위험**이고,
> 대부분 **순수익이 마이너스**다. 강하게 재고를 권한다.

### 왜 위험한가
- 애드센스 정책: "광고 노출이 주목적인 페이지로 유료 트래픽을 보내는 것"
  금지. 구글애즈 정책: 목적지(랜딩) 가치 요건. → 적발 시 **애즈 계정 +
  애드센스 계정 동반 위험**(승인된 자산을 잃을 수 있음).

### 왜 돈이 안 되는가 (순수익 관점)
- 건강 분야 애드센스 RPM ≈ $10 = **방문 1회당 약 10~30원** 수익.
- 그런데 건강 키워드 구글애즈 클릭 단가(CPC)는 보통 **수백~수천 원**.
- 즉 **클릭 1번 사오는 비용 > 그 방문이 버는 애드센스 수익.** 매출은
  늘어 보여도 순수익은 줄거나 마이너스. "월 2천 순수익" 목적과 정반대.

### 구글애즈가 *말이 되는* 경우
유료 광고는 "광고 보여주는 페이지"가 아니라 **돈을 버는 전환**으로 보낼 때만
의미 있다:
- 내 **상품/서비스** 판매 (클릭당 단가 < 전환 1건의 수익)
- **이메일/리드 수집** 후 장기 수익화
- 클릭 비용보다 비싼 **제휴(어필리에이트) 오퍼**

### 권장
- **검색 유입(SEO)은 공짜다.** 순수익 목표에는 이게 정답.
- 광고 예산은 트래픽 사오기 대신 **① 키워드/SEO 도구, ② 콘텐츠 제작
  속도(AI), ③ (정 쓰려면) 전환 있는 랜딩**에 쓴다.
- bodybalance-labo 에 애즈를 돌리고 싶다면, 그 페이지가 **애드센스가 아니라
  내 상품/리드 수집**을 향하게 바꾼 뒤에만.

> 이 결정(애즈를 멈출지/전환형으로 바꿀지)은 당신 몫이다. 다만 "월 2천
> 순수익"이 목적이라면, 데이터·정책·경제성 모두 **SEO 집중**을 가리킨다.

## 1) 블로그별 활용 플랜

| 블로그 | 역할 | 분야/클러스터 | 주당 발행 | 수익모델 | 우선순위 |
|--------|------|---------------|:---:|----------|:---:|
| `finwiz.tistory.com` | 수익 엔진 1 | 대출(전세·신용·정책자금) | 3 | 애드센스(고RPM) | ★★★ |
| `bodybalance-labo.com` | 수익 엔진 2 | 건강(질환관리·영양·수면) | 3 | 애드센스(고RPM) | ★★★ |
| `calculator.seaga.co.kr` | 트래픽 허브 | 계산기(대출이자·만나이·BMI) | 1~2 | 애드센스 + 내부링크 | ★★ |
| `seaga.co.kr` | 브랜드 허브/보조 | 잡블로그(이슈·정책) | 1 | 애드센스 | ★ |
| `seaga2/4/5.tistory.com` | 보조(기존 유지) | 기존 주제 | 0~1 | 애드센스 | ☆ |

핵심 원칙:
- **수익 엔진 2개에 주당 발행의 60% 이상**을 집중.
- 계산기 사이트는 "신규 양산"이 아니라 **기존 유틸 → 고단가 글로 내부링크**.
- 보조 블로그는 신규 투자 최소화, 죽이지도 않고 키우지도 않는 유지 모드.

## 2) 발행량 계획 (90일 램프)

1인 + AI 초안 기준. **YMYL 글 1편 검수·사실확인에 30~60분**이 든다는 전제
(품질이 곧 순위이므로 여기서 타협하지 않는다).

| 기간 | 주당 총 발행 | 배분 | 목표 |
|------|:---:|------|------|
| 1~3주 | 2~3 | 키워드 지도 구축 + 시범 발행 | 파이프라인·검수 흐름 정착 |
| 4~8주 | 4~5 | 수익 엔진에 집중 | **첫 클러스터(12~15편) 완성** |
| 9~12주 | 4~6 | 1클러스터 보강 + 2클러스터 착수 | 트래픽 견인 글 굳히기 |

> "주 20편 양산"보다 **"주 4~5편, 검수 통과, 한 클러스터 완성"** 이 순위·
> 순수익에서 이긴다. 양산 자동화의 속도는 *발행*이 아니라 *초안·리서치*에 쓴다.

## 3) 키워드 운영 — 어떻게 나누고 어떻게 찾나

### 3단 구조로 나눈다
```
분야(Niche)  →  클러스터(Cluster)  →  개별 키워드(롱테일)
대출         →  전세자금대출        →  "신혼부부 전세자금대출 소득기준 2026"
건강         →  신장병 관리         →  "만성신장병 식단 피해야 할 음식"
```

### 사이트에 클러스터를 배정한다
- `finwiz` ← 대출 클러스터(전세자금대출, 신용대출, 정책자금대출 …)
- `bodybalance-labo` ← 건강 클러스터(신장병관리, 공황장애, 수면, 다이어트 …)
- `calculator` ← 계산기 키워드(대출이자계산, 만나이, BMI) → 위 글로 링크

한 사이트가 **여러 클러스터를 동시에 벌이지 않는다.** 한 클러스터를
끝내고 다음으로. (토픽 어소리티가 분산되지 않게.)

### 발굴 워크플로 (도구 → 검증 → 배정)
1. **발굴(자동):** `python -m src.run_pipeline keywords --niche "<클러스터>" --count 30`
   → 고단가·저경쟁 롱테일 후보 + 점수.
2. **검증(사람, 무료):**
   - Search Console: 이미 노출되는데 11~30위인 쿼리 = **최우선**(가장 빠른 성과)
   - 구글 자동완성 / 연관검색 / "사람들이 묻는 질문(PAA)" 로 변형·하위질문 수집
   - 실제 구글 검색 1페이지 확인(대형 사이트 도배면 더 좁은 롱테일로)
3. **배정:** 검증된 키워드를 클러스터 시트에 넣고 상태 부여(아래 칸반).

### 키워드 시트(칸반)로 관리
구글시트/노션에 컬럼: `키워드 | 클러스터 | 사이트 | 의도 | 가치 | 경쟁 |
상태(백로그→초안→검수→발행→추적) | URL | 현재순위`. 이게 운영의 중심
대시보드가 된다.

## 4) 자동화 흐름 상세 (end-to-end)

```
[1] 키워드 발굴        (자동) keyword_planner — Claude
        │
[2] 검증·배정          (사람) Search Console + 시트
        │
[3] 초안 생성          (자동) content_brief — Claude  → drafts/*.md
        │  + 이미지 자동 생성(기존 자동화 재사용)
        │
[4] 검수·사실확인·보강  (사람) ★ 게이트 — docs/04 체크리스트
        │
[5] 업로드(draft 비공개) (자동) wordpress_publisher / make
        │
[6] 최종 확인 → 공개     (사람) WP 관리자
        │
[7] 색인 요청           (반자동) Search Console
        │
[8] 성과 추적 → 환류     (반자동→사람) 11~30위 글을 [1]로
```

### make.com 의 역할 (재배선)
- 기존 "양산 자동발행" 시나리오 → **"검수 통과분만 발행"** 으로 바꾼다.
  즉 make는 [5] 업로드와 [7] 색인요청, [8] 데이터 수집·알림 같은
  **반복 노동**만 담당하고, **[4] 검수와 [6] 공개 결정은 사람**이 쥔다.
- 트리거 예: 시트에서 상태가 "검수완료"로 바뀐 행 → make가 해당 초안을
  워드프레스 draft로 업로드 → 슬랙/카톡으로 "공개 검토 요청" 알림.

### 자동 vs 사람 (절대 규칙)
- 자동화 OK: 발굴, 초안, 이미지, 업로드, 색인요청, 데이터 수집, 알림
- 사람 전용: **검수(게이트), 공개 결정.** 이 두 개를 자동화하면 페널티.

## 5) 측정·환류 (매주 금요일)
- Search Console: 노출↑/순위↑ 글 = 보강 후보, 무노출 글 = 정리 후보.
- 애드센스: 어느 클러스터가 실제 RPM·수익을 내는지 → 다음 클러스터 선택에 반영.
- 시트의 `현재순위` 갱신 → 11~30위는 다음 주 [1] 보강 백로그로.
