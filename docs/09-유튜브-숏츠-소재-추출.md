# 09. 유튜브 숏츠 소재 추출

유튜브 링크와 시작·끝 시간을 주면 그 구간만 잘라 파일로 저장한다.
숏츠 제작 파이프라인의 **1단계**다.

```
[1] 링크 + 시작/끝 시간 → 구간 추출     ← 지금 여기 (src/youtube_clipper.py)
[2] 9:16 세로 변환 + 자막 삽입          (예정)
[3] 업로드                              (예정)
```

---

## 1. 설치

```bash
pip install -r requirements.txt      # yt-dlp 포함

# ffmpeg 는 pip 로 안 깔린다. 시스템에 직접 설치한다.
brew install ffmpeg                  # macOS
sudo apt install ffmpeg              # Ubuntu/Debian
winget install Gyan.FFmpeg           # Windows
```

`ffmpeg -version` 이 나오면 준비 끝이다.

> yt-dlp 는 유튜브 변경에 맞춰 자주 업데이트된다.
> 다운로드가 갑자기 안 되면 **먼저** `pip install -U yt-dlp` 부터 해본다.

---

## 2. 기본 사용법

### 영상 정보부터 확인 (다운로드 없음)

```bash
python -m src.run_pipeline clip --url "https://www.youtube.com/watch?v=NSYfVe36jw0" --info
```

제목·길이·라이선스·자막 유무와 **챕터 목록**을 보여준다.
챕터가 있으면 어느 구간을 자를지 고르기 쉽다.

### 구간 하나 추출

```bash
python -m src.run_pipeline clip \
  --url "https://www.youtube.com/watch?v=NSYfVe36jw0" \
  --start 1:30 --end 2:10
```

→ `outputs/clips/NSYfVe36jw0_00-01-30_00-02-10_<제목>.mp4`

### 길이로 지정 (숏츠는 이 방식이 편하다)

```bash
python -m src.run_pipeline clip --url "..." --start 1:30 --duration 45
```

### 링크에 붙은 시간(t=) 그대로 쓰기

유튜브에서 "현재 시간부터 공유"로 복사한 링크를 그대로 넣으면
`t=` 값을 시작 시간으로 쓴다.

```bash
python -m src.run_pipeline clip --url "https://youtu.be/NSYfVe36jw0?t=95" --duration 40
```

### 한 영상에서 여러 클립 뽑기

```bash
python -m src.run_pipeline clip --url "..." \
  --range 1:30-2:10 --range 5:00-5:45 --range 12:20-12:55
```

구간이 2개 이상이면 **원본을 한 번만 내려받아** 로컬에서 여러 번 자른다.
같은 영상에서 계속 뽑을 거면 `--keep-source` 로 원본을 남겨두면
다음 실행부터는 다운로드 없이 즉시 잘린다.

---

## 3. 시간 표기

| 쓰는 법 | 뜻 |
|---|---|
| `90`, `90.5` | 초 |
| `1:30` | 1분 30초 |
| `01:02:03` | 1시간 2분 3초 |
| `00:01:30.5` | 1분 30.5초 |
| `1m30s`, `1h2m3s`, `45s` | 단위 표기 |

구간(`--range`)은 `1:30-2:10`, `1:30~2:10`, `90-130` 모두 된다.

---

## 4. 옵션

| 옵션 | 설명 |
|---|---|
| `--start` / `--end` / `--duration` | 시작, 끝(또는 시작부터의 길이) |
| `--range 시작-끝` | 구간을 한 번에 지정. 여러 번 반복 가능 |
| `--out 폴더` | 저장 위치 (기본 `outputs/clips`) |
| `--name 이름` | 저장 파일 이름 지정 |
| `--quality 720` | 최대 세로 해상도 (기본 1080) |
| `--audio-only` | 음성만 mp3 로 (자막 원고·팟캐스트용) |
| `--fast` | 재인코딩 없이 빠르게 컷 — **정확도 문제 있음, 아래 참고** |
| `--keep-source` | 원본을 `outputs/sources/` 에 남겨 재사용 |
| `--cookies` / `--cookies-from-browser chrome` | 연령제한·로그인 필요 영상 |
| `--info` | 다운로드 없이 정보만 확인 |
| `--dry-run` | 실행할 명령만 출력 |

---

## 5. 왜 기본이 '정밀 컷'인가

영상은 키프레임 단위로만 잘라낼 수 있다. 재인코딩 없이(`-c copy`) 자르면
**지정한 시간이 아니라 그 앞의 키프레임에서 시작**한다.

실제로 측정한 값이다(키프레임 간격 10초인 영상에서 5.5초~9.25초 = 3.75초를 요청):

| 모드 | 요청 | 실제 결과 |
|---|---|---|
| 정밀 컷 (기본) | 3.75초 | **3.77초** (요청대로) |
| `--fast` | 3.75초 | 9.36초 (0초부터 시작해버림) |

숏츠는 **첫 1~2초가 이탈률을 결정**한다. 시작점이 몇 초 밀리면 소재로 못 쓴다.
그래서 경계 부분만 재인코딩하는 정밀 컷을 기본으로 둔다. 조금 느리지만
30~60초 클립에서는 체감 차이가 거의 없다.

`--fast` 는 "대충 어디쯤인지만 보면 되는" 확인용으로만 쓴다.

## 6. 동작 방식

```
구간 1개  →  yt-dlp --download-sections 로 그 구간만 부분 다운로드
             (빠르고 트래픽이 적다)

구간 2개+ →  원본 1회 다운로드 → ffmpeg 로 로컬에서 N번 컷
             (매번 다시 받는 것보다 훨씬 빠르다)
```

출력 코덱은 H.264 + AAC(mp4)로 고정한다. 프리미어·다빈치·캡컷 등
편집 프로그램과 숏츠 업로드 양쪽에서 문제가 가장 적은 조합이다.

---

## 7. 저작권 (중요)

남의 영상을 잘라 그대로 숏츠로 올리면 **저작권 클레임 또는 채널 경고** 대상이다.
수익 창출도 막힐 수 있다. 이 도구는 다음 용도를 전제로 만들었다.

- 내가 올린 영상에서 숏츠용 클립을 뽑을 때
- CC(크리에이티브 커먼즈) 라이선스 영상 — `--info` 의 `라이선스` 항목으로 확인
- 해설·자막·재구성이 들어가 **변형 저작물**로 볼 수 있는 콘텐츠

원본을 그대로 재업로드하는 용도라면, 유튜브가 공식 제공하는
"리믹스 → 숏츠로 편집" 기능을 쓰는 편이 안전하다(자동 출처 표기, 60초 제한).

## 8. 문제 해결

| 증상 | 대응 |
|---|---|
| `'yt-dlp' 을(를) 찾을 수 없습니다` | `pip install -r requirements.txt` |
| `'ffmpeg' 을(를) 찾을 수 없습니다` | 위 1번 설치 항목 참고 |
| `Sign in to confirm you're not a bot` | `--cookies-from-browser chrome` 추가 |
| 연령제한 영상 | 로그인된 브라우저 쿠키 사용 (`--cookies-from-browser`) |
| 갑자기 전부 실패 | `pip install -U yt-dlp` (유튜브 변경 대응) |
| 회사망·서버에서 403 | 유튜브 도메인이 차단된 환경이다. 로컬 PC에서 실행 |
