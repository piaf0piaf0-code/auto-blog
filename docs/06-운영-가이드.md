# 06. 운영 가이드 — 네트워크를 매주 어떻게 굴릴 것인가

글쓰기는 목적이 아니라 공정 하나다. 이 문서는 "공장 전체를 어떻게
돌리는가"를 정의한다. 공장에는 **컨베이어(파이프라인)** 와 **품질검사(검수)**,
그리고 **계기판(측정)** 이 있어야 한다.

> 운영 철학 한 줄: **"글을 많이 찍는다"가 아니라 "검색 신뢰 자산을 매주
> 조금씩, 옳은 방향으로 쌓는 공장을 돌린다."**

---

## 1) 운영의 3개 축

1. **자산 역할 분담** — 어느 블로그가 무슨 일을 하는가 (수익/유입/보조)
2. **콘텐츠 컨베이어** — 키워드가 글이 되어 발행·추적되기까지의 상태 흐름
3. **측정과 환류** — 무엇이 먹히는지 보고, 먹히는 쪽에 다음 주를 투자

---

## 2) 사이트별 역할 (네트워크 운영도)

블로그마다 "직업"을 준다. 모든 블로그가 똑같이 글만 쌓으면 안 된다.

| 사이트 | 직업(역할) | 이번 분기 할 일 |
|--------|-----------|----------------|
| `finwiz.tistory.com` (대출) | **수익 엔진 1** | 대출 토픽 클러스터 1개 완성 |
| `bodybalance-labo.com` (건강) | **수익 엔진 2** | 건강 토픽 클러스터 1개 완성(워프=자동화 용이) |
| `calculator.seaga.co.kr` (계산기) | **트래픽 유입 + 내부링크 허브** | 대출/BMI 계산기 → 관련 고단가 글로 연결 |
| `seaga.co.kr` (잡블로그) | **브랜드 허브/보조** | 유지, 신규 투자 최소화 |
| `seaga2/4/5.tistory.com` | **보조** | 유지, 클러스터 외 신규 양산 금지 |
| 네이버 블로그 ×2 | **보조 유입(수익 채널 아님)** | 시간 투자 최소화 |
| `sa.*`, `01.sa.*` (애즈 연결) | **🛑 중단/전환 대상** | 아비트라지·브리지 구조 폐기 |

핵심: **고단가 수익 엔진 2개에 노력의 80%.** 나머지는 유지보수 모드.

## 3) 기존 자동화 자산 정리 (keep / fix / stop)

현재 진행 중인 자동화들을 전략 기준으로 분류한다. (정확한 내부 동작은
세션 내용 공유가 필요 — 아래 "확인 필요" 참고)

| 기존 자동화 | 판정 | 이유 / 조치 |
|-------------|------|-------------|
| 워프 이미지 생성 | ✅ KEEP | 이미지 자동 생성은 안전하고 생산성↑ |
| 티스토리 글 초안 자동화 | 🔧 FIX | 초안 생성은 유지, **무검수 자동발행은 중단**(검수 게이트 삽입) |
| 계산기(대출/BMI) | ✅ KEEP | 유틸 트래픽 자산 → 고단가 글로 내부링크 강화 |
| **워프자동화 MAKE (광고이상건으로 중지)** | 🛑 STOP→조사 | **원인 규명 전 재가동 금지.** 아래 리스크 운영 참고 |
| 티스토리 자동저장 | 🔧 FIX | 발행 빈도·품질을 클러스터 전략에 맞춰 재설정 |
| 맞춤형 동화책 | 🔍 분리 평가 | 애드센스 블로그와 별개 제품. 본 전략과 분리해 따로 판단 |

> "STOP→조사"가 가장 중요하다. 광고 이상으로 자동화를 멈췄다는 건, 이미
> 한 번 정책/품질 경고선에 닿았다는 뜻이다. 같은 방식으로 재가동하면 승인된
> 계정이 위험해진다.

---

## 4) 주간 운영 루틴 (1인 기준 예시)

매주 같은 리듬으로 돈다. 즉흥적으로 글 쓰지 않는다.

| 요일 | 작업 | 도구 |
|------|------|------|
| 월 | 키워드 발굴 + 이번 주 발행 목록 확정(3~5개) | `keywords` + Search Console |
| 화~목 | 초안 생성 → 검수·사실확인·보강 → draft 업로드 | `brief` → 사람 → `publish` |
| 목 | 워드프레스에서 최종 확인 후 공개 + 색인 요청 | WP 관리자 + Search Console |
| 금 | 성과 측정 + 다음 주 우선순위 환류(11~30위 글 보강 선정) | Search Console |

주 3~5편이면 충분하다. **양보다 클러스터 완성도와 검수 품질.**

---

## 5) 콘텐츠 상태 흐름 (칸반 보드로 관리)

글은 항상 아래 7단계 중 한 칸에 있다. 구글시트/노션/트렐로로 추적한다.

```
① 키워드 백로그   →  ② 초안 생성됨(drafts/)  →  ③ 검수 대기
   →  ④ 검수·사실확인 완료  →  ⑤ draft 업로드  →  ⑥ 공개+색인요청
   →  ⑦ 추적 중(보강/유지/통합 결정)
```

- ③→④ 사이에 **품질 체크리스트(docs/04)** 가 게이트.
- ⑦에서 데이터로 보강/유지/삭제를 결정 → 그 결과가 ①로 환류.

---

## 6) KPI와 의사결정 규칙

매주 보는 숫자(추측 금지, 데이터로):

| 지표 | 출처 | 의미 |
|------|------|------|
| 노출수(impressions) | Search Console | 색인·노출되고 있나 |
| 평균 게재순위 | Search Console | 1페이지(상위 10) 근처인가 |
| 클릭수 / CTR | Search Console | 제목·메타가 매력적인가 |
| 색인된 페이지수 | Search Console | 양산 페이지가 누락/제외되진 않나 |
| RPM / 수익 | 애드센스 | 고단가 분야가 실제로 도는가 |

**의사결정 규칙(자동 판단 기준):**
- 11~30위로 노출되는 글 → **최우선 보강**(가장 빠른 성과).
- 공개 후 3개월간 노출 0 → 내용 통합 또는 삭제(씬 콘텐츠 정리).
- 클릭은 적은데 노출 많음 → 제목/메타만 개선(글 새로 안 씀).
- 한 클러스터가 트래픽 견인 시작 → 다음 클러스터로 확장.

---

## 7) 역할 분담 — 자동 vs 사람

| 자동(코드/make) | 사람 |
|-----------------|------|
| 키워드 발굴·점수화 | 발행 목록 최종 결정 |
| 초안·메타·이미지 생성 | 사실확인·보강·검수(게이트) |
| draft 업로드, 스케줄 | 공개 전환 결정 |
| 성과 데이터 수집 | 보강/삭제/확장 판단 |

**검수(게이트)와 최종 공개 결정은 절대 자동화하지 않는다.** 이게 방어선이다.

---

## 8) 리스크 운영 (최우선)

1. **MAKE 워프자동화 "광고이상건" 원인 규명** — 재가동 전 반드시.
   - 애드센스 정책 위반 경고였나? 무효 트래픽(invalid traffic)이었나?
     광고 게재 제한이었나? 원인에 따라 대응이 완전히 다르다.
2. **아비트라지/브리지 구조 폐기** (`sa.*`, `01.sa.*`).
3. **계정 리스크 분산** — 수익·트래픽을 한 애드센스 계정에 몰지 않기.
4. **정책 준수** — 무검수 양산·중복 콘텐츠·과밀 광고 금지(docs/04).

---

## 9) 다음에 확정할 것 (자료 받으면 업데이트)

- 현재 make.com 시나리오 구성(blueprint) → 이 운영도에 맞춰 재배치
- "광고이상건"의 정확한 원인 → 리스크 운영 1번 확정
- 티스토리 자동화의 발행 빈도/방식 → 주간 루틴에 반영

이 세 가지가 채워지면 운영 체계가 "현재 자산에 딱 맞는 실행 매뉴얼"로 완성된다.
