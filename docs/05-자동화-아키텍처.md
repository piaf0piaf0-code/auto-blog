# 05. 자동화 아키텍처

현재 make.com + Claude Code를 쓰고 있다. 이 저장소는 그것을 *대체*하는 게
아니라, **검수 게이트가 있는 안전한 파이프라인**으로 정리한다.

## 1) 전체 파이프라인

```
┌──────────────┐   ┌──────────────┐   ┌──────────────┐   ┌───────────────┐
│ 1. 키워드     │ → │ 2. 초안 생성  │ → │ 3. 사람 검수  │ → │ 4. 발행        │
│ 기회 발굴     │   │ (검색의도)    │   │ (품질 게이트) │   │ (draft→공개)   │
│ keyword_planner│  │ content_brief │   │ 사람          │   │ wordpress_pub │
└──────────────┘   └──────────────┘   └──────────────┘   └───────────────┘
        │                  │                                       │
        └─ Claude API ─────┘                              워드프레스 REST API
                                                          (티스토리는 수동/RSS)

      ┌──────────────────────────────────────────────────────────┐
      │ 5. 성과 추적 (Search Console) → 다음 키워드 우선순위로 환류 │
      └──────────────────────────────────────────────────────────┘
```

**핵심:** 3번(사람 검수)은 자동화하지 않는다. 이게 페널티 방어선이다.

## 2) 무엇을 무엇으로 자동화하나

| 단계 | 도구 | 비고 |
|------|------|------|
| 키워드 발굴 | `src/keyword_planner.py` (Claude) | seed → 점수화된 후보 |
| 검색의도/초안 | `src/content_brief.py` (Claude) | 마크다운 초안 + 메타 |
| 검수 | **사람** | 품질 체크리스트(04) |
| 워드프레스 발행 | `src/wordpress_publisher.py` (REST API) | 기본 `draft` |
| 스케줄·오케스트레이션 | make.com 또는 cron | 아래 참고 |
| 성과 추적 | Search Console API (확장 예정) | 11~30위 글 환류 |

## 3) make.com 과의 연결 (3가지 방식 중 택1)

이 저장소 코드를 make.com 흐름에 어떻게 끼울지:

- **(A) make.com을 오케스트레이터로** — make의 시나리오가 정해진 시각에
  이 코드(웹훅/서버 엔드포인트 또는 셸 단계)를 호출해 키워드·초안을
  생성하고, 결과를 구글시트/노션에 적재 → 사람 검수 → 승인 시 발행 모듈 호출.
- **(B) 코드를 메인으로, make는 알림만** — cron이 `run_pipeline`을 돌리고,
  완료/검수요청을 make 웹훅으로 보내 슬랙/카톡 알림.
- **(C) 완전 코드 기반** — cron + 이 저장소만. make 미사용.

> 어느 쪽이 맞는지는 **현재 make 시나리오 구조**에 달려 있다.
> (사용자에게 현재 make 모듈 구성을 받아 이 문서에 맞춰 확정 예정.)

## 4) 플랫폼별 발행 가능성

| 플랫폼 | 자동 발행 | 방법 |
|--------|-----------|------|
| 워드프레스 | ✅ 가능 | REST API + Application Password (`wordpress_publisher.py`) |
| 티스토리 | ⚠️ 제한적 | 공식 API 종료. 수동 발행 또는 비공식 자동화(주의) |
| 네이버 | ❌ 사실상 불가 | 정책상 자동화 비권장. 수동 운영. |

→ **자동화 투자 우선순위는 워드프레스(`bodybalance-labo`, `seaga`, `calculator`).**
티스토리(`finwiz`)는 콘텐츠 초안까지 자동, 발행은 수동이 안전하다.

## 5) 모델 선택

- 기본 모델: **`claude-opus-4-8`** (지능·비용 균형). 코드에 설정됨.
- 더 어려운 장기 작업이 필요하면 `claude-fable-5`로 교체 가능
  (`src/config.py`의 `MODEL` 변경).

## 6) 비용 감각 (대략)

- 키워드 30개 발굴: 1회 수백~수천 원 수준
- 글 초안 1편(2,000자): 수백 원 수준
- 월 100편 초안: 수만 원대 → 고단가 글 1편이 한 달 벌어주면 회수.

자세한 비용은 실제 사용량으로 재측정한다.
