# make.com 시나리오를 Claude가 읽게 하는 법

Claude(이 세션)는 **다른 Claude Code 세션의 내용이나 make.com 계정에 직접
접근하지 못한다.** 대신, 시나리오를 **Blueprint(JSON)로 내보내 이 폴더에
넣으면** 모듈 구성·연결·데이터 매핑·필터까지 정확히 읽을 수 있다.

---

## 방법 1: Blueprint 내보내기 (권장 — 가장 정확하고 안전)

1. make.com → 해당 시나리오 열기
2. 우측 하단(또는 상단) **⋯ 더보기 메뉴** 클릭
3. **Export Blueprint** 선택 → `.json` 파일 다운로드
4. 그 파일을 `make/blueprints/` 폴더에 넣는다
   (예: `make/blueprints/워프자동화-MAKE.json`)
5. Claude에게 "blueprint 확인해줘"라고 말하면 읽고 분석한다

> ⚠️ **붙여넣기/커밋 전 민감정보 제거:** Blueprint에는 보통 자격증명(토큰)이
> 들어가지 않지만, **웹훅 URL, 데이터스토어 ID, 이메일, 사이트 URL** 등이
> 포함될 수 있다. 외부에 공유하기 전에 이런 값은 `***` 등으로 가린다.
> (시나리오 *구조*만 알면 분석에는 충분하다.)

## 방법 2: 스크린샷 (보조)

시나리오 캔버스 전체 스크린샷을 채팅에 첨부. 모듈 흐름의 큰 그림은
보이지만, 각 모듈의 매핑/필터 세부는 안 보인다. Blueprint와 병행 권장.

## 방법 3: make.com API / MCP (고급 — 권한 주의)

make.com은 API 토큰으로 시나리오 목록·blueprint를 프로그래밍 방식으로
가져올 수 있다. 다만:
- API 토큰은 **계정 전체 권한**을 가질 수 있어 신중해야 한다.
- 이 실행 환경의 **네트워크 정책**상 외부(make.com)로의 접근이 막혀
  있을 수 있다(환경 설정에 따라 다름).
- 따라서 1인 운영 단계에서는 **방법 1(Blueprint 파일)** 이 가장 안전하고 충분하다.

대량·상시 연동이 필요해지면 그때 API 연동을 별도로 설계한다.

---

## 어떤 시나리오부터 넣으면 좋은가 (우선순위)

스크린샷에서 본 세션 기준, 분석 가치가 높은 순서:

1. **워드프레스 자동화 (make.com, 구축 중)** — 발행 흐름이 검수를 거치는지
   확인해 검수 게이트로 재배선하기 위해. 이 blueprint가 가장 중요.
2. **티스토리 글/이미지 자동화** — 발행 빈도·품질을 클러스터 전략에 맞게
   재설정하기 위해.
3. **티스토리 자동저장** — 발행 흐름 파악용.
4. 워프 이미지 생성 — 유지(keep) 판정이지만 흐름 파악에 도움.

## 폴더 규칙

```
make/
├── README.md            # 이 파일
└── blueprints/          # 여기에 *.json blueprint 를 넣는다
    └── (예: 워프자동화-MAKE.json)
```

Blueprint를 넣은 뒤 Claude에게 분석을 요청하면, 결과를
`docs/05-자동화-아키텍처.md` / `docs/06-운영-가이드.md` 에 반영한다.
