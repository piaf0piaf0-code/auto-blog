# 꿈해몽 프롬프트 바꾸기

## 무엇이 달라지나

| | 예전 | 새것 |
| --- | --- | --- |
| 시스템 프롬프트 | 1,398자 | 449자 |
| 사용자 프롬프트 | 4,341자 | 775자 |
| **합계** | **5,739자** | **1,224자** (79% 감소) |
| 요구 분량 | 7,000~9,000자 | 3,000~4,500자 |

꿈해몽 글에 필요 없던 규칙이 전부 빠졌습니다.

```
ETF     5회 → 0회        접수기간  5회 → 0회
레버리지 3회 → 0회        채용     4회 → 0회
스포츠   4회 → 0회        논란     5회 → 0회
롱테일  32회 → 0회
```

지시를 줄인 만큼 **재료(검색 참고자료)의 비중이 커집니다.**
지시가 많으면 모델은 지키기 쉬운 것부터 지킵니다. 글자 수와 소제목 개수는
지키기 쉽고, "검색자가 궁금한 사실"은 어렵습니다.

## 새 프롬프트가 시키는 것

1. 도입 — 이 꿈을 꾸고 검색한 사람의 마음부터
2. `<h2>` 대분류 4~6개 — 롱테일에서 뽑기
3. 각 대분류 아래 `<h3>` 꿈 예시 3~6개
   각 예시는 **그 장면의 감정 → 그 감정에 따른 해석 → 현실에서 점검할 것**
4. `<h2>최종 정리하면,</h2>`

예시 제목을 검색어처럼 짓게 했습니다.

```
좋은 예 : 고양이가 나를 할퀴는 꿈
나쁜 예 : 고양이 꿈의 부정적 해석 1
```

그리고 이런 것을 막았습니다.

- 예언처럼 단정하기 (`~하게 됩니다`)
- 재물운·복권·대박으로 기대 부추기기
- 병 진단하기
- 링크 지어내기 (`seaga4.tistory.com` 만 허용)

## 적용

1. 지금 쓰시는 `blog_content_pipeline.py` 를 **다른 이름으로 복사해 백업**
   (예: `blog_content_pipeline_백업.py`)
2. 받으신 `blog_content_pipeline.py` 로 덮어쓰기

`.env` 는 고치지 않아도 됩니다.

## 되돌리기

마음에 안 드시면 `.env` 에 **이 한 줄만** 넣으면 예전으로 돌아갑니다.

```
DREAM_PROMPT_V2=0
```

코드를 되돌릴 필요가 없습니다. 확인해 봤습니다 — 이 값을 `0` 으로 두면
예전 프롬프트와 **글자 하나까지 똑같습니다.**

## 확인한 것

```
꿈해몽에 새 프롬프트가 실제로 쓰이나            ○
DREAM_PROMPT_V2=0 이면 예전과 완전히 동일       ○
최신이슈·정책지원·대출관련·신장정신·웰빙 그대로  ○
참고자료가 없을 때도 안전하게 처리              ○
MIN_ARTICLE_CHARS(2,500자) 검사 통과            ○
```

**꿈해몽 외 다른 카테고리는 한 글자도 안 건드렸습니다.**

## 써 보시는 법

```
1. 오늘작성에 꿈해몽 키워드 하나만 '글쓰기대기'로 두기
2. python blog_content_pipeline.py
3. 나온 글을 예전 글과 비교
```

한 편만 돌려 보시고 판단하시면 됩니다. 비용도 한 편치입니다.

> 전에 OpenAI 401 오류가 났던 것이 아직 안 풀렸으면 2번이 안 됩니다.
> 그것부터 확인이 필요합니다.
